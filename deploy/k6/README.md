# Сценарий k6

`pii-guard.js` это независимая проверка сервиса маскирования инструментом k6.
Собственные генераторы `cmd/loadgen` и `cmd/sonar` и k6 считают задержку
разным кодом, поэтому совпадение их чисел означает, что измеритель не врёт.

k6 уже установлен на машине генератора нагрузки (`89.169.172.236`), ставить
ничего не нужно.

## Запуск

Через общий скрипт, он сам положит сценарий на машину генератора:

```
scripts/loadtest.sh k6 --remote --url http://10.129.0.22 --rps 1000 --duration 5m
make load-opinion URL=http://10.129.0.22
```

Вручную на машине генератора:

```
ssh ubuntu@89.169.172.236
cd /home/ubuntu/pii-loadtest
BASE_URL=http://10.129.0.22 RPS=1000 DURATION=5m PAYLOAD_SIZE=250 k6 run pii-guard.js
```

## Настройки через переменные окружения

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `BASE_URL` | `http://127.0.0.1:8080` | адрес сервиса без пути |
| `RPS` | 200 | пар запросов в секунду, то есть вдвое меньше самих запросов |
| `DURATION` | `1m` | длительность прогона |
| `PAYLOAD_SIZE` | 250 | размер текста в байтах |
| `VUS` | `max(50, RPS/5)` | сколько отправителей выделить заранее |
| `SYSTEM_KEY` | пусто | значение заголовка `X-System-Key` |
| `P99_MS` | 50 | порог доли 99 задержки на каждом шаге |
| `ERROR_RATE` | 0.01 | допустимая доля ошибочных ответов |
| `RETRIES` | 2 | сколько раз повторить запрос при ответе 429 |

## Что проверяет сценарий

Одна итерация это пара запросов по контракту:

1. прямой шаг: ответ обязан отличаться от входа, иначе персональные данные
   ушли бы дальше открытым текстом;
2. обратный шаг: та же маска с тем же `payload_id`, ответ обязан совпасть
   с исходным текстом побайтово.

Пороги прогона: доля 99 задержки по каждому шагу ниже `P99_MS`, доля ошибок
ниже `ERROR_RATE`, доля верных масок и точных восстановлений выше 0.99.
Если порог не выдержан, k6 завершается ненулевым кодом, и это видно
в выводе скрипта и в `make`.

Ответ 429 не считается ошибкой: по контракту это просьба повторить запрос,
сценарий повторяет его до `RETRIES` раз и считает такие ответы в показателе
`pii_throttled`.

## Отдача показателей в Prometheus

```
K6_PROMETHEUS_RW_SERVER_URL=http://10.129.0.22:9090/api/v1/write \
K6_PROMETHEUS_RW_TREND_STATS=p(95),p(99),max \
k6 run -o experimental-prometheus-rw pii-guard.js
```

Prometheus обязан быть запущен с ключом `--web.enable-remote-write-receiver`,
иначе запись будет отвергнута с кодом 404. Кроме того порт 9090 должен быть
открыт для машины генератора: на день проверки он слушал на машине сервиса,
но с генератора не отвечал, потому что группа безопасности открывает наружу
только 22, 80, 443 и 3000, а правило для внутреннего трафика выписано на сеть
10.128.0.0/16, тогда как машины стоят в 10.129.0.0/24. Через общий скрипт это
включается так:

```
K6_OUT=experimental-prometheus-rw \
K6_EXTRA_ENV='K6_PROMETHEUS_RW_SERVER_URL=http://10.129.0.22:9090/api/v1/write' \
scripts/loadtest.sh k6 --remote --url http://10.129.0.22
```

После этого в Grafana доступны ряды `k6_http_req_duration`,
`k6_http_reqs_total`, `k6_pii_mask_changed` и `k6_pii_demask_exact`
рядом с показателями самого сервиса.
