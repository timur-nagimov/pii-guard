# Источники набора для проверки качества

Набор для проверки качества собирается из нескольких источников. Собственная
генерация даёт объём и управляемое покрытие типов, но проверяет сервис на
данных, которые мы сами и придумали. Внешние источники дают независимую
разметку: её делали без оглядки на наши детекторы, поэтому качество на ней
честнее.

Данные набора в репозиторий не кладутся, каталог `corpus/` в `.gitignore`.
В репозиторий идут только программы сбора (`tools/`) и одна проба
`testdata/sample.jsonl`, порождённая нашим собственным генератором. Проб из
внешних источников в репозитории нет ни одной: ни из набора на Hugging Face,
ни из Википедии, ни из наборов отзывов. Причина в лицензиях, см. последний
раздел этого документа.

## Единый формат

Строка JSON на элемент, кодировка UTF-8:

```json
{"id":"hf-ru-pii-000000","category":"hf_ru_pii","source":"hf_ru_pii","text":"...","spans":[{"start":10,"end":25,"type":"FIO"}],"partial_labels":true}
```

Смещения `start` и `end` заданы **в байтах** исходного текста, а не в символах.
Это важно: в Python срезы строк идут по символам, в Go по байтам, а
кириллическая буква занимает два байта. Любые смещения из внешних источников
переводятся в байтовые и проверяются срезом.

Поле `partial_labels: true` означает, что размечены не все персональные данные
текста. У таких элементов изменения за пределами размеченных фрагментов не
считаются ошибкой.

## hf_ru_pii: wolframko/russian-pii-66k

### Описание

Русскоязычный набор синтетических клиентских сообщений (аренда, бронирование,
подписки, поддержка, оплата) с пофрагментной разметкой персональных данных.
Разметка чужая, к нашему сервису отношения не имеет.

| Свойство | Значение |
|---|---|
| Адрес | `https://huggingface.co/datasets/wolframko/russian-pii-66k` |
| Опубликован | 15.02.2026 |
| Строк в источнике | 65 652 |
| Язык | `ru`, локаль `RU`, все строки без исключения |
| Колонки | `source_text`, `privacy_mask`, `language`, `locale` |
| Разметка | список словарей с ключами `start`, `end`, `label`, `value`, смещения в символах |
| Меток в источнике | 17 различных |

### Лицензия

**Лицензия автором не указана.** В карточке набора на huggingface.co нет поля
`license`, README содержит только описание схемы. Схема меток
(`GIVENNAME`, `SURNAME`, `TELEPHONENUM`, `BUILDINGNUM` и прочие) совпадает со
схемой семейства `ai4privacy/pii-masking`, то есть набор с большой
вероятностью производный от него, а там условия ограничивают коммерческое
использование.

Практический вывод:

1. Набор пригоден для внутреннего замера качества.
2. Данные набора не распространяем: `corpus/` исключён из репозитория и из
   архива с исходным кодом.
3. Проба из этого набора в репозиторий НЕ попадает: лицензия не объявлена.
   Если условия распространения важны, пробу стоит заменить на собственную
   генерацию, а этот файл держать локально.

### Как собрать

```bash
python3 tools/fetch_ru_pii.py \
    --out corpus/ru_pii_66k.jsonl \
```

Скрипт идёт двумя путями. Основной: один файл parquet на весь набор, требует
`pyarrow` (`python3 -m pip install --user pyarrow`). Запасной: постраничная
выдача `datasets-server.huggingface.co/rows` по сто строк за вызов, включается
сама при отсутствии `pyarrow` либо принудительно флагом `--rows-api`. Скачанный
parquet кэшируется во временном каталоге, повторный запуск сети не требует.

чужую сущность, но в русской локали там лежит внутренний паспорт.

или пароль засчитался бы как ложное срабатывание.

### Склейка соседних фрагментов

Источник размечает имя и фамилию двумя фрагментами, а адрес тремя и более.
Наш набор хранит их одним фрагментом, как это уже принято в собственной
генерации (`ADDRESS` вида `село Махачкала, проезд Мира, д. 96, к. 225`).

Склейка идёт только через допустимый разделитель:

* имя и фамилия склеиваются, если между ними ровно один пробел либо ничего;
* компоненты адреса склеиваются через пробелы, запятые и служебные сокращения
  (`д.`, `дом`, `ул.`, `улица`, `г.`, `корп.`, `кв.`, `стр.` и подобные).

Через прозаические вставки склейки нет. Это не формальность: в источнике
встречаются гапы вида `", фамилия "`, `" по адресу "`, `" в городе "`,
`" и улицу "`. Склеив через них, мы включили бы в эталонный фрагмент обычный
текст и занизили бы оценку сервиса на ровном месте.

Индекс (`ZIPCODE`) в адрес не склеивается: у нас это отдельный тип `POSTCODE`.

### Проверка смещений

Смещения источника заданы в символах, наш формат требует байтов. Проверка
трёхступенчатая, и ни одна ступень не дала ни одного отказа на всех 65 652
строках.

1. **До перевода**, в символах: `text[start:end] == value`. Отсеивает
   рассогласование самого источника.
2. **После перевода**, в байтах: `text.encode('utf-8')[bs:be].decode('utf-8')`
   обязано совпасть с `text[start:end]`. Байтовые смещения считаются по
   массиву накопленных длин `len(ch.encode('utf-8'))`.
3. **Независимая проверка готового файла** отдельным кодом, не тем, что писал
   набор: границы попадают на начало руны (`byte & 0xC0 != 0x80`), срез
   декодируется, фрагмент непустой, без ведущих и хвостовых пробелов и
   присутствует в тексте. Результат: 63 249 элементов, 141 873 фрагмента,
   0 битых.

### Объём результата

| Показатель | Значение |
|---|---|
| Прочитано строк источника | 65 652 |

| Выброшено | 2 403 (3.66%) |
| С `partial_labels: true` | 25 355 (40.1%) |

| Размер `corpus/ru_pii_66k.jsonl` | 27.6 МБ |

Выброшены ровно те строки, где **все** метки оказались вне нашего перечня
(только `USERNAME`, `ACCOUNTNUM`, `PASSWORD`). Ни одного фрагмента такая
строка не даёт, а при `partial_labels: true` изменения вне разметки не
считаются, поэтому в замере она бесполезна. Отбраковки по несовпадению
смещений не было ни одной.

### Что источник вскрыл в сервисе

**`ADDRESS`, 0.40.** В источнике 6 539 строк, где весь адрес это один
населённый пункт без улицы и дома (`ст. Якша`, `д. Касимов`, `клх Тутаев`).
Замер в разрезе префикса населённого пункта:

| Префикс | Изменено | Затронуто | Фрагментов |
|---|---|---|---|
| `к.` | 0.0481 | 7.3% | 887 |
| `ст.` | 0.0993 | 16.1% | 915 |
| `клх` | 0.1444 | 19.8% | 929 |
| `с.` | 0.2969 | 31.5% | 947 |
| `г.` | 0.3094 | 33.1% | 934 |
| `д.` | 0.3133 | 32.9% | 971 |
| `п.` | 0.3221 | 33.8% | 937 |

Проседает не один редкий префикс, а весь сценарий: даже привычное `г.` даёт
33%. Похоже, детектор адреса требует якоря в виде улицы или дома и одиночный
населённый пункт не берёт.

**`FIO`, 0.72.** Промахи собраны на редких и устаревших славянских именах:
`Гремислав`, `Кондратий`, `Велимир`, `Лучезар`, `Евграф`, `Моисей`. Видны два
разных случая. Одиночное имя без фамилии не находится вовсе. В паре фамилия
маскируется, а имя нет, и фрагмент получает примерно 0.4 вместо единицы
(`Уважаемый Гремислав Гришин` превращается в `Уважаемый Гремислав ******`).
Это прямое указание расширить словарь личных имён.

### Что не получилось

* Лицензия набора автором не объявлена, условия распространения выяснить не
  удалось. Подробности выше в разделе про лицензию.
* Метки `USERNAME`, `ACCOUNTNUM`, `PASSWORD` (в сумме 34 746 фрагментов)
  пропадают из замера: нашего типа для них нет, а `partial_labels` снимает
  учёт изменений вне разметки. Поведение сервиса на номерах счетов и паролях
  этот источник не проверяет ни в одну, ни в другую сторону.
* Набор синтетический по происхождению, просто сгенерированный не нами. Он
  даёт независимость разметки, но не даёт настоящей грязи живого текста
  (опечаток, переносов, смешанной раскладки).

## Лицензии и что попадает в архив с кодом

Набор `wolframko/russian-pii-66k` используется только для измерения качества у себя. Автор не объявил лицензию, а схема меток совпадает с семейством `ai4privacy/pii-masking`, где условия ограничивают коммерческое использование. Поэтому ни сам набор, ни проба из него в репозиторий и в архив с исходным кодом не попадают: каталог `corpus` и каталог `tools` исключены. В репозитории остаются только программы сбора и собственные, порождённые нами данные.

Тексты Википедии распространяются по лицензии CC BY-SA, тексты отзывов взяты из наборов без объявленной лицензии. Ни те, ни другие в репозиторий и в архив не попадают.

Единственная проба, которая лежит в репозитории, это `testdata/sample.jsonl`: она целиком порождена собственным генератором `cmd/gen`, значения в ней вымышленные, и распространять её можно свободно. Всё остальное воспроизводится двумя командами, описанными выше.

Проверить, что в репозитории нет чужих данных, можно так:

```bash
git ls-files 'testdata/*.jsonl' | xargs grep -l '"source":"hf_ru_pii"\|"source":"reviews"\|"source":"wikipedia"'
```

Команда не должна найти ничего.

Воспроизвести набор можно двумя командами, они описаны выше в этом документе.
