# Формат маскирования

Документ описывает, во что сервис превращает найденные персональные данные. Эталонного формата у организаторов нет, формат выбирает участник, поэтому здесь он зафиксирован целиком и однозначно. Ссылка на этот документ передаётся вместе с решением.

## Правило по умолчанию: пресет `full`

Одно предложение, которое описывает формат полностью:

> Каждая руна внутри найденного фрагмента персональных данных заменяется на звёздочку `*`, число рун сохраняется, за пределами фрагмента не меняется ни один байт.

Из этого следуют три свойства:

- **Текст нечитаем и невосстановим.** По маске нельзя узнать ни значение, ни его длину в символах исходного алфавита, только число знаков.
- **Позиции сохранены.** Соседние фрагменты не сдвигаются, разметка исходного текста остаётся валидной для маски.
- **Формат воспроизводим.** Описание не содержит спорных понятий вроде «разделитель», поэтому другой человек получит тот же результат.

## Что входит в фрагмент

Фрагмент это само значение вместе с внутренними разделителями, но без слов-ярлыков перед ним.

| Входит в фрагмент | Не входит |
|---|---|
| цифры, буквы значения | ярлык перед значением: `паспорт`, `тел.:`, `ИНН`, `email`, `дата рождения:` |
| внутренние пробелы, точки, дефисы, скобки, знак `+`, знак `@` | знаки препинания, отделяющие значение от остального текста |
| разделяющие слова внутри сущности: `серия 4509 номер 123456` | перевод строки, фрагмент никогда его не пересекает |

Ведущие и хвостовые пробелы и знаки препинания обрезаются перед маскированием.

## Другие пресеты

Вид маскирования настраивается отдельно для каждой системы-потребителя и для каждого типа. Это требование о гибкой настройке: разным потребителям нужны разные маски.

| Пресет | Правило | Пример | Когда применять |
|---|---|---|---|
| `full` | все руны фрагмента в `*` | `Иванов Иван` → `***********` | по умолчанию, максимальная защита |
| `full_ws` | всё в `*`, пробелы сохранены | `Иванов Иван` → `****** ****` | когда важно видеть число слов |
| `partial` | видны два первых и два последних значащих знака, разделители на месте; при менее чем шести значащих знаках маскируется всё | `4509 123456` → `45** ****56` | показ человеку, когда нужен признак для сверки |
| `initials` | имя сворачивается до инициалов, длина не сохраняется | `Иванов Иван Иванович` → `И. И. И.` | только для имён и только для систем с ключом доступа |
| `token` | типизированный плейсхолдер с номером | `Иванов Иван` → `[FIO_1]` | обращение к языковой модели |
| `synthetic` | правдоподобная подстановка того же типа | `Иванов Иван` → `Киселев Пахом` | демонстрация, когда нужен связный текст |

Пресеты `initials`, `token` и `synthetic` не сохраняют длину, поэтому системе без ключа доступа они запрещены: это проверяет валидатор настроек при загрузке.

## Вид `synthetic`: правдоподобная подстановка

Вид `synthetic` заменяет значение персональных данных другим значением того же
типа и той же формы. Подстановка детерминирована: одно и то же значение в одном
запросе всегда получает одну и ту же подстановку, а разные значения — разные,
без коллизий в пределах запроса. Значение по подстановке не восстанавливается:
сид берётся от хеша значения, а не от самого значения.

| Тип | Значение | Подстановка |
|---|---|---|
| ФИО | `Иванов Иван Иванович` | `Киселев Пахом Сергеевич` |
| ФИО женское | `Петрова Мария Сергеевна` | `Борисова Ануш Андреевна` |
| ФИО с инициалами | `Иванов И. И.` | `Гуськов Р. Р.` |
| ФИО латиницей | `IVAN IVANOV` | `Rozhdestvenskiy Askold` |
| Имя держателя карты | `IVAN IVANOV` | `Rozhdestvenskiy Askold` |
| Телефон | `+7 (916) 123-45-67` | `+7 (900) 056-34-30` |
| Электронная почта | `ivanov@mail.ru` | `ijapkv@example.com` |
| Номер карты | `4111 1111 1111 1111` | `4111 4127 6121 2724` |
| ИНН | `500100732259` | `541614121248` |
| СНИЛС | `112-233-445 95` | `456-769-016 32` |
| Дата рождения | `12.03.1985` | `09.02.1996` |
| Адрес | `г. Москва, ул. Ленина, д. 5, кв. 12` | `г. Рига, ул. Ленина, д. 5, кв. 12` |
| Место рождения | `г. Ленинград` | `г. Мурманск` |
| Индекс | `101000` | `901834` |
| Гражданство | `Россия` | `Израиль` |
| Код подразделения | `770-001` | `787-476` |
| Водительское удостоверение | `77 АА 123456` | `25 ХП 032707` |
| Код безопасности | `123` | `185` |
| Пин-код | `4321` | `9876` |

Правила подстановки по типам:

- **ФИО и держатель карты** — другое имя того же пола и той же формы: три слова
  остаются тремя словами, инициалы — инициалами, латиница — латинским именем.
  Пол определяется по отчеству, имени или окончанию фамилии.
- **Телефон** — номер того же формата: разделители и код страны сохраняются,
  цифры абонента заменяются, используется резервный код оператора 900.
- **Электронная почта** — другой адрес на домене `example.com` с сохранением
  формы локальной части.
- **Номер карты** — число, проходящее проверку Луна, с тестовым префиксом
  `4111` или `5555`, той же длины и с теми же разделителями.
- **ИНН и СНИЛС** — числа с правильными контрольными суммами.
- **Даты** — другая дата в том же формате записи и в правдоподобном диапазоне.
- **Адрес, место рождения, индекс** — другой город из словаря, другой индекс.
- **Гражданство** — другая страна из словаря.
- **Остальные типы** — другая строка той же формы: буквы заменяются буквами,
  цифры — цифрами, разделители сохраняются.

Подстановки попадают в `Placeholders` так же, как у вида `token`: пара
«подстановка → исходное значение» сохраняется, и обратное преобразование
возвращает исходный текст побайтово. Если модель просклоняла подстановку имени
в ответе (родительный или дательный падеж), склонённая форма тоже заменяется
исходным значением.

## Почему для обращения к языковой модели нужен `token`

Звёздочки и инициалы модель в ответе не сохраняет: она перескажет текст своими словами, и восстановить исходное значение будет не из чего. Типизированный плейсхолдер вида `[FIO_1]` модель переносит в ответ как есть, поэтому сервис возвращает пользователю настоящие данные. Одинаковые значения в пределах одного запроса получают один и тот же плейсхолдер, поэтому смысл запроса для модели сохраняется: она видит, что речь об одном и том же человеке.

## Обратное преобразование

Обратное преобразование возвращает исходную строку побайтово. Оно опирается не на разбор маски, а на сохранённое соответствие: сервис хранит зашифрованный исходный текст, связанный с идентификатором запроса. Поэтому формат маски может быть каким угодно, в том числе необратимым по своему виду, и это не мешает восстановлению.
